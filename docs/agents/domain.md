# Domain documentation

This repository uses a single domain context.

Before exploring or changing an area, read these when present:

- `CONTEXT.md` at the repository root for shared terminology.
- Relevant decisions under `docs/adr/`.

Proceed silently when either is absent. Create or update domain documentation only when a real term or durable decision needs recording.

Use the repository's established names in specifications, tests, and reviews. Surface any conflict with an existing architectural decision instead of silently overriding it.
