# v6.3.0-beta.7 fresh review-session specification

## Problem

The beta.6 Clear All recovery let a saved draft choose the new active account.
Because an already-open tab can contain a stale username and CSRF token, a tab
from an earlier session could reclaim cleared state after the browser had logged
in to another Letterboxd account. Chrome could also retain an empty `$legacy`
account shell that blocked legitimate reactivation. After a legitimate review
did reactivate state, the extension popup could still appear signed out.

## Required behaviour

- Saving a draft never selects or replaces the active account.
- Review submission fetches an uncached, same-origin Letterboxd film page and
  confirms its signed-in username immediately before any production-log POST.
- A fresh account mismatch, signed-out response, failed fetch, oversized page,
  timeout, or malformed account header blocks submission and preserves the draft.
- After Clear All, the clearing tab forgets its cached FilmState account and uses
  `$legacy` until fresh verification succeeds.
- Every other open tab adopts the newer `$legacy` root, cancels pending
  pre-clear debounced saves, and cannot make a stale `mergeAccount` command
  authoritative. Only explicit account activation can change ownership.
- A freshly verified account may claim either an absent reset account or an empty
  `$legacy` account shell, but may never replace a different real account. The
  service worker performs this as a serialized compare-and-set against the
  review editor's captured clear generation, with no retry or local fallback.
- Watched, Like, and Watchlist actions remain blocked while FilmState is
  `$legacy`; the legacy exception is limited to the review recovery path.
- Successful verification restores `vypode_user`, so the popup recognises the
  active Letterboxd session without a page reload.
- Failed or mismatched verification marks the cached popup session inactive.
- The popup session cache is observational only. Active or inactive cache writes
  cannot select or replace the authoritative FilmState account; v2 migration
  remains the sole compatibility exception.
- Film JSON is fetched before the final identity check. Its account-bound token
  takes precedence over any token in the older open document, and a login change
  between those GETs is rejected before the production-log request.

## Regression expectations

- Review delivery, duplicate-prevention locks, account and generation fences,
  trailer controls, dictation, Skip, Undo, and automatic pagination retain their
  existing behaviour.
- The release package contains only the ten runtime extension files; installed
  review skills and repository documentation are not included.
- The visible release identifier is `v6.3.0-beta.7` everywhere it is current and
  user-facing.
